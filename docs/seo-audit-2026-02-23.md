# QuranCircle SEO Audit - 2026-02-23

## Executive Summary
QuranCircle has solid foundational security headers and good desktop performance, but several indexation and canonicalization issues are limiting SEO reliability for the canonical `https://www.qurancircle.io` property.

Top priorities:
1. Canonical host inconsistency (`www` redirects in transport, but metadata and sitemap emit non-`www` URLs).
2. Missing canonical tags across key pages.
3. Auth/private flows are exposed as indexable `200` pages with generic homepage metadata (`/account`, `/reset-password`, and likely `/my-circles`).
4. Mobile CWV risk (LCP above 2.5s on `/` and `/browse`; CLS above threshold on `/browse`).

Business impact for "Khatm coordination" intent:
- Ranking signals are diluted across host variants and duplicate metadata.
- Crawl/index quality can degrade due soft-404-like and private-page indexing patterns.
- Mobile experience can suppress competitive ranking where intent is mobile-heavy.

## Findings

### Critical Indexation and Canonical Issues

#### 1) Canonical host mismatch across stack
- Impact: High
- Evidence:
  - `https://qurancircle.io` returns `307` to `https://www.qurancircle.io/`.
  - Home and browse metadata emit `og:url` as `https://qurancircle.io`.
  - `robots.txt` references `Sitemap: https://qurancircle.io/sitemap.xml`.
  - `sitemap.xml` `<loc>` entries use `https://qurancircle.io`.
- Code trace:
  - `/Users/ahmet/Documents/Alpaylabs/QuranCircle/app/layout.tsx:52`
  - `/Users/ahmet/Documents/Alpaylabs/QuranCircle/app/robots.ts:11`
  - `/Users/ahmet/Documents/Alpaylabs/QuranCircle/app/sitemap.ts:6`
  - `/Users/ahmet/Documents/Alpaylabs/QuranCircle/lib/site-url.ts:5`
- Fix:
  - Set `NEXT_PUBLIC_SITE_URL=https://www.qurancircle.io` in production.
  - Regenerate metadata/sitemap/robots on canonical host only.

#### 2) Missing canonical tags on key pages
- Impact: High
- Evidence:
  - No `<link rel="canonical">` found on `/`, `/browse`, `/my-circles`, `/account`, `/reset-password`.
- Code trace:
  - Layout metadata has no `alternates.canonical` object.
  - `/Users/ahmet/Documents/Alpaylabs/QuranCircle/app/layout.tsx:52`
- Fix:
  - Add canonical per indexable route via `alternates: { canonical: ... }`.
  - For noindex pages, canonical should still be explicit where appropriate.

#### 3) Auth/private routes return indexable `200` pages
- Impact: High
- Evidence:
  - `/account` and `/reset-password` return HTTP `200` with no `meta name="robots"` noindex.
  - Both ship generic homepage title/description and rely on client-side redirect.
  - `/my-circles` is also indexable and metadata-exposed despite user-specific behavior.
- Code trace:
  - `/Users/ahmet/Documents/Alpaylabs/QuranCircle/app/account/page.tsx:98`
  - `/Users/ahmet/Documents/Alpaylabs/QuranCircle/app/reset-password/page.tsx:46`
  - `/Users/ahmet/Documents/Alpaylabs/QuranCircle/app/my-circles/page.tsx:4`
- Fix:
  - Move auth gating to server boundary for these routes.
  - Add `robots: { index: false, follow: false }` for private/auth pages.
  - Consider returning redirect/401/403 server-side when unauthenticated.

#### 4) Dynamic invalid short-code pages behave like soft 404 (`200` + noindex)
- Impact: High
- Evidence:
  - `/s/INVALID1` responds `HTTP/2 200` while rendering not-found metadata (`Circle Not Found`) and `meta robots noindex` with `NEXT_HTTP_ERROR_FALLBACK;404` marker.
  - Plain unknown routes (for example `/this-page-does-not-exist`) correctly return HTTP `404`.
- Code trace:
  - `/Users/ahmet/Documents/Alpaylabs/QuranCircle/app/s/[shortCode]/page.tsx:59`
- Fix:
  - Ensure invalid short-code route returns true HTTP 404 in production (not fallback streamed 200).
  - Verify runtime/caching configuration for this segment and notFound boundary behavior.

### High-Impact On-Page Issues

#### 5) `/browse` metadata duplicates homepage
- Impact: Medium
- Evidence:
  - `/browse` title and description are identical to home.
  - `h1` is specific ("Browse Community Khatms"), but head metadata is generic.
- Code trace:
  - `/Users/ahmet/Documents/Alpaylabs/QuranCircle/app/browse/page.tsx:1` (no route metadata export)
- Fix:
  - Add route-specific metadata targeting browse intent (for example, public khatm circles, join a juz, community recitation).

#### 6) OG/Twitter URL and image host use non-canonical domain
- Impact: Medium
- Evidence:
  - OG and Twitter URL/image tags emit `https://qurancircle.io/...` while canonical transport host is `www`.
- Code trace:
  - `/Users/ahmet/Documents/Alpaylabs/QuranCircle/app/layout.tsx:61`
  - `/Users/ahmet/Documents/Alpaylabs/QuranCircle/app/s/[shortCode]/page.tsx:24`
- Fix:
  - Align all social metadata URLs to canonical `www` host through site URL config.

#### 7) Sitemap `lastmod` churns on every request
- Impact: Medium
- Evidence:
  - Consecutive requests two seconds apart produce different `<lastmod>` timestamps for static pages.
- Code trace:
  - `/Users/ahmet/Documents/Alpaylabs/QuranCircle/app/sitemap.ts:11`
  - `/Users/ahmet/Documents/Alpaylabs/QuranCircle/app/sitemap.ts:17`
- Fix:
  - Use stable `lastmod` for static routes (deploy timestamp, commit timestamp, or explicit constant).
  - Keep dynamic event lastmod tied to content updates (not request time).

### Content and Trust Signals

#### 8) Missing trust/legal pages in crawlable IA
- Impact: Medium
- Evidence:
  - `/privacy`, `/terms`, `/contact`, and `/about` return 404.
  - Footer includes disabled "About" button.
- Code trace:
  - `/Users/ahmet/Documents/Alpaylabs/QuranCircle/components/footer.tsx:38`
- Fix:
  - Add crawlable pages for Privacy, Terms, and Contact at minimum.
  - Replace disabled About button with real internal link.

#### 9) No structured data (JSON-LD)
- Impact: Low
- Evidence:
  - No `application/ld+json` present on audited pages.
- Fix:
  - Add Organization/WebSite schema site-wide.
  - Add Event-like schema where appropriate for public circles if semantics fit product data.

#### 10) Limited indexable footprint
- Impact: Medium
- Evidence:
  - Current sitemap contains only 2 URLs (`/` and `/browse`), with no public `/s/*` entries at audit time.
  - Crawl depth check from `/` found only `/browse`, `/my-circles`, and `/manifest.json` within 3 clicks (unauthenticated crawl).
- Fix:
  - Ensure public circles are consistently surfaced and linked when available.
  - Add evergreen informational pages for "Khatm coordination" keyword coverage.

### Technical Performance and CWV (Lighthouse)

#### 11) Mobile LCP above threshold
- Impact: Medium
- Evidence (Lighthouse mobile):
  - `/`: LCP 4.11s (target < 2.5s)
  - `/browse`: LCP 3.45s
- Fix:
  - Optimize above-the-fold render path and reduce JS hydration work.

#### 12) `/browse` mobile CLS slightly above threshold
- Impact: Medium
- Evidence:
  - Lighthouse mobile CLS on `/browse`: 0.11 (target < 0.10)
- Fix:
  - Reserve layout space for dynamic blocks/skeleton transitions and stabilize initial paint dimensions.

#### 13) High unused JS budget
- Impact: Low
- Evidence:
  - Lighthouse reports ~126 KiB estimated unused JavaScript across tested pages.
- Fix:
  - Defer or split non-critical bundles and trim hydration payloads.
